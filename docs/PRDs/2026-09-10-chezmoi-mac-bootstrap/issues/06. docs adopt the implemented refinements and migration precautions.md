### Rewrite `04. migrate this mac.md` so it is runnable

The steps below replace or extend what 04 says today; keep its shape and its `needs-human: true`.

- **Config first, then re-init.** `.chezmoi.toml.tmpl:14-16` uses `promptBoolOnce`, and `~/.config/chezmoi/chezmoi.toml` on this Mac already stores `personal = false`. A second `chezmoi init` does not re-ask, and `chezmoi init --promptBool personal=true` does not change a stored answer either (verified in an isolated HOME in the safety review). So: edit the file by hand (`personal = true`, `embedded` as wanted), then `chezmoi init --source ~/repos/caillou/dotfiles` to regenerate it from the current template, then confirm with `chezmoi data | grep personal`. 04's current line 16 ("answers: managed no, personal yes") cannot work.
- **fisher 3 goes before the apply.** This Mac runs `fisher version 3.2.9` from `~/.config/fish/functions/fisher.fish`, with a `fishfile` and no `fish_plugins`. Script 20's guard is `functions --query fisher`, true under fisher 3, so it skips the bootstrap and runs `fisher update`, which fisher 3 does not have: "fisher update failed" on every apply, forever. After the backup: `fish -c 'fisher self-uninstall'`, remove the old `fishfile`, then apply and open a new fish to check the prompt. Do this before the universal-variable purge, since fisher 3 keeps its package list in one.
- **Remove the two symlinks:** `rm ~/.hammerspoon/keyboard ~/.hammerspoon/Spoons/EmmyLua.spoon`. chezmoi replaces `init.lua` only; both symlinks dangle once `~/repos/keyboard` goes. 04 currently says the apply replaces the `keyboard` symlink, which it does not.
- **Backup, before the script apply,** in addition to the existing tar: `tmutil localsnapshot` (one command, covers everything below, restorable per file), then a `defaults export` of every domain script 60 writes, because cfprefsd caches them and a tar of the plist files can be stale: `NSGlobalDomain`, `com.apple.finder`, `com.apple.dock`, `com.apple.WindowManager`, `com.apple.screencapture`, `com.apple.HIToolbox`, `com.apple.desktopservices`, `com.apple.AppleMultitouchTrackpad`, `com.apple.driver.AppleBluetoothMultitouch.trackpad`, `com.apple.assistant.support`, `com.apple.speech.recognition.AppleSpeechRecognition.prefs`, `com.apple.symbolichotkeys` (it holds every custom keyboard shortcut and the script replaces the whole domain), plus `com.googlecode.iterm2` and `defaults -currentHost export NSGlobalDomain`.
- **iTerm2 export.** Both profiles carry `Working Directory = /Users/caillou` (export lines 893 and 1344). Set each profile's working directory to "Home directory" (Profiles > General) and quit iTerm2 before exporting; afterwards `grep -n '/Users/' .iterm2/com.googlecode.iterm2.plist` must print nothing and `file .iterm2/*.plist` must say XML. Run `tests/secrets-check.sh` before committing it.
- **Expect one CoreBrightness import,** not a no-op: two of the four display entries carry no `AutoBrightnessEnable` key, so the first apply writes the flag, imports, restarts `corebrightnessd` and may flicker the brightness, with one sudo prompt. 04 line 23 says "a true no-op" today.
- **Expect a second Automation consent prompt,** for System Settings: `run_onchange_after_60-defaults.sh.tmpl:34` sends it an Apple Event, and every (sender, target) pair prompts once. On this Mac the wallpaper is already a solid colour, so the System Events prompt is skipped and this is the one that appears.
- **Run the display script twice** on the new Mac and check that the second run imports nothing and restarts no daemon. Carry the same check into `05. bootstrap and verify the new mac.md`, which keeps `needs-human: true`.
