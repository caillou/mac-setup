# Homebrew installer fails loudly on an empty download

## PRD

[2026-09-10-chezmoi-mac-bootstrap](../prd.md)

Captured values, commands and sources are in [research-notes.md](../research-notes.md).

## What to build

Make a failed download of the Homebrew installer abort the apply instead of being recorded as a successful run.

- The defect, from the final right-thing review: `.chezmoiscripts/run_once_before_00-homebrew.sh.tmpl:23-24` is `NONINTERACTIVE=1 /bin/bash -c "$(curl -fsSL ...)"`. Under `set -eu` a failing command substitution inside an argument does not abort the script, and `bash -c ""` exits 0. Demonstrated: `sh -c 'set -eu; /bin/bash -c "$(curl -fsSL https://invalid.invalid/x)"; echo continued'` prints `continued` and exits 0. chezmoi then keys the run-once script as done, Homebrew is never installed, and re-running the bootstrap never reaches the installer again: recovery is `chezmoi state delete-bucket --bucket=scriptState`, which the README names only as the wrong bucket to delete (`README.md:94-96`). A captive portal or a DNS hiccup in the first minute of a fresh bootstrap leaves the machine there, so story 45 does not hold.
- Fix: `curl -fsSL "$URL" -o "$tmp"` into a `mktemp` file with a trap that removes it; require the file to be non-empty and to look like a shell script (first line starts with `#!`); then `NONINTERACTIVE=1 /bin/bash "$tmp"`. On a curl failure, an empty file or a missing shebang, print one line naming the reason and `exit 1`, so chezmoi records nothing and the next apply retries. A real installer failure (non-zero exit from the script itself) already aborts and is unchanged.
- Move `sudo -v` and its "macOS asks for your admin password" line after a successful download, so a failed download does not cost a password.
- The script must still not include the shared preamble: chezmoi keys a run-once script by rendered content, and `tests/scripts.bats:42-47` pins `0` occurrences of `template "facts.sh"`. Write the guard in plain POSIX sh with no helper from `facts.sh`.
