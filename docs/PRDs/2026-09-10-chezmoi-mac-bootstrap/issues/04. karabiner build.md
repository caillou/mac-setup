## What to build

Generate the Karabiner rules from the karabiner.ts source kept inside the dotfiles repo.

- Copy the source from the karabiner.ts repo into a project directory in the dotfiles repo: the single TypeScript rules file, `package.json`, the lockfile, a minimal tsconfig. Drop the starter README; a few lines in the dotfiles README replace it. Pin `karabiner.ts` and `tsx` to exact versions instead of `latest`.
- Exclude the directory from the home directory via `.chezmoiignore`.
- Change-triggered script, hashed on the source and lockfile, guarded on Karabiner being installed: `npm ci` then the build, which writes the rules into Karabiner's config file, preserving its other settings. Runs after asdf so node is available.
- Change the target profile from the user-named profile to "Default profile", which Karabiner creates on first launch, so no profile has to be created by hand. Karabiner must have been launched once; the manual checklist covers that.
- Per the Karabiner research in the notes: keep karabiner.ts (maintained, 1.38.0, covers KE 16); pin it as `^1.38.0` with a committed lockfile; keep `tsx` as the runtime; add a `dev` script `tsx watch src/index.ts` for iterating; keep the `update` script for deliberate bumps. Alternatives (goku, kanata, KE's own JS evaluator) were evaluated and rejected.
- The generated `karabiner.json` never enters the repo.
