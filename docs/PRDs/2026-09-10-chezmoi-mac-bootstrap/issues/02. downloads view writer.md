## What to build

Make Downloads open in list view, Date Added column visible, sorted by Date Added descending, by writing the folder's view record into the parent folder's `.DS_Store`.

- A small Python module: a function that takes the parent store path and ensures the `Downloads` record has `vstl` type `Nlsv`, `vSrn` long 1, and an `lsvC` blob (binary plist) with `sortColumn = dateAdded` and the `dateAdded` column visible and descending. It merges into an existing `lsvC` when one is there, falls back to the blob captured from the personal Mac (base64 in the research notes) when the record is missing, creates the store when missing, and writes nothing when the record is already correct. Read-back function that decodes the blob's sort column. Never write `lsvp`/`lsvP`; Finder 26 reads `lsvC`.
- The module lives in the source dir at `.downloads-view/ensure_downloads_view.py` (dot-prefixed, so chezmoi ignores it). A change-triggered script (`run_onchange_after_62-downloads-view.sh.tmpl`, a pure writer, hashed on the module) exits with a message when `uv` is not installed yet (the README documents `chezmoi state delete-bucket --bucket=scriptState` to force change-triggered scripts to run again), otherwise runs `killall Finder || true`, waits a second, runs the module with `uv run --with ds_store python3 <path>`, then `killall Finder || true` again.
- Python unit tests against a temporary store: write, read back, assert the three entries, the decoded `sortColumn == dateAdded`, and that Date Added is visible. Tests run in CI.
- Verified working on macOS 26.6 on both Macs with the overwrite variant of this procedure. Research (see notes) found no supported or cleaner alternative: Finder's AppleScript dictionary has no Date Added column, defaults templates don't reach folders with their own record, and UI scripting via System Events or Hammerspoon is unverified and brittle.
- Optionally also set `FK_DefaultListViewSettingsV2:sortColumn` to `dateAdded` via `defaults export com.apple.finder -`, edit, `defaults import com.apple.finder -` (never by editing the plist file) so folders without their own record match.
