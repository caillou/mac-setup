## What to build

`run_after_90-report.sh.tmpl` runs on every apply and prints the checklist of what macOS won't let a script do, tailored to the machine. It computes what it can live and reads markers only for what it can't.

- Always, when the app exists: Privacy & Security approvals for Karabiner and Hammerspoon (Input Monitoring, Accessibility, driver extension); Karabiner first launch when `~/.config/karabiner/karabiner.json` is missing; first dictation activation and language model downloads; verify pointer speed in System Settings unless `marked pointer-speed-applied`; verify auto-brightness unless `marked auto-brightness-applied`.
- When `marked ssh-key-generated`: paste the public key into Azure DevOps, with the key printed. The README documents removing the marker (or the script offers `rm`) once done.
- Unmanaged: when the `packages-status` marker is non-zero, say which `brew bundle` entries failed if the log has them, and that a signed-out App Store is the usual cause: sign in and re-run apply.
- Managed: the apps from the data table (casks and App Store rows in the enabled groups) whose bundle is absent from /Applications, computed now, to request via Self Service.
- The script never fails the apply. Its rendering is covered by a render test with fake data; the live parts by bats with a stubbed Applications directory and state directory.
