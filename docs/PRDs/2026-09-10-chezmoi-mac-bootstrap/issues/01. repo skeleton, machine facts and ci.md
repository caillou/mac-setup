## What to build

Turn this repo into a chezmoi source directory with the scaffolding every later issue plugs into.

- chezmoi config template (`.chezmoi.toml.tmpl`): detects MDM enrollment with `profiles status -type enrollment` into a `managed` boolean that the user can override in the generated config; prompts once (`promptBoolOnce`) for the group flags `personal` and `embedded`; sets `sourceDir` from `{{ .chezmoi.sourceDir }}` (the path given with `--source` at init), never a literal path, so the same template works on the CI runner.
- Shared script preamble as a chezmoi template include, `.chezmoitemplates/facts.sh`, inlined into every script with `{{ template "facts.sh" . }}`. It contains: `set -eu`, Homebrew shellenv, `~/.asdf/shims` on PATH, the state directory `~/.local/state/dotfiles/` (created), and pure predicates: `is_managed`, `app_present "<App name>"` (bundle in /Applications), `has_command`, `default_is <domain> <key> <value>`, `hs_available` (Hammerspoon running via `pgrep -x Hammerspoon` and the `hs` CLI on PATH), plus `mark <name>` / `marked <name>` helpers for marker files. Scripts are separate `sh` processes, so nothing exported in one script reaches the next; the include is the only mechanism.
- Fixed script filenames under `.chezmoiscripts/`, all templates, all with explicit attributes (only the Homebrew one is `before`; everything else is `after` so all dotfiles exist before scripts run):
  - `run_once_before_00-homebrew.sh.tmpl`
  - `run_onchange_after_10-packages.sh.tmpl`
  - `run_onchange_after_20-fish-plugins.sh.tmpl`
  - `run_once_after_21-login-shell.sh.tmpl`
  - `run_once_after_30-github-and-ssh.sh.tmpl`
  - `run_onchange_after_40-asdf.sh.tmpl`
  - `run_onchange_after_50-karabiner.sh.tmpl`
  - `run_onchange_after_60-defaults.sh.tmpl`
  - `run_onchange_after_61-dock.sh.tmpl`
  - `run_onchange_after_62-downloads-view.sh.tmpl`
  - `run_onchange_after_63-iterm2.sh.tmpl`
  - `run_onchange_after_64-display.sh.tmpl`
  - `run_after_90-report.sh.tmpl`
  Later issues fill these in; they must not invent other names.
- Repo-only content in dot-prefixed directories where possible (`.karabiner/`, `.iterm2/`, `.github/`), which chezmoi ignores without rules; `docs/`, `tests/`, `README.md` and `lefthook.yml` listed in `.chezmoiignore`. Data files under `.chezmoidata/` (the cask table lives there, defined in the Brewfile issue).
- Test harness: bats for the facts template (render it with `chezmoi execute-template`, then test the functions with stubbed `profiles`, `ls`, `command`, `pgrep`); a bats test asserting the script filenames and attributes above; shellcheck over rendered scripts; lefthook running all of it before commit.
- GitHub Actions job on a macOS runner: install chezmoi, `chezmoi init --source "$GITHUB_WORKSPACE"` with fake config data (`managed=false`, `personal=false`, `embedded=false`), `chezmoi apply --dry-run --verbose`. Dry-run validates templates and file targets only; it does not execute scripts. Script content is checked by rendering with `execute-template` in the tests, not by dry-run.
- The old README content and the 2023 `macos` script stay in place for now; later issues replace them.

## Acceptance criteria

- [ ] `chezmoi init --source <checkout>` on a clean HOME renders a config with `managed`, `personal`, `embedded` and a `sourceDir` equal to the path passed
- [ ] `managed` is true when the enrollment command reports MDM enrollment and false otherwise; an override in the config wins
- [ ] bats tests cover every predicate in the facts template, both outcomes each, and assert the fixed script filename list
- [ ] shellcheck passes on every rendered script; lefthook runs bats and shellcheck before commit
- [ ] the GitHub Actions macOS job passes a dry-run apply on a fresh runner
- [ ] `chezmoi managed` lists no repo-only files
