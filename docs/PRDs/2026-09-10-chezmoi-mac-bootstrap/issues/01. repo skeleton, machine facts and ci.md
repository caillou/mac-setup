## What to build

Turn this repo into a chezmoi source directory with the scaffolding every later issue plugs into.

- chezmoi config template (`.chezmoi.toml.tmpl`): detects MDM enrollment with `profiles status -type enrollment` and feeds the result as the default into `promptBoolOnce . "managed" "Managed by an employer" <detected>`, so the stored answer survives re-inits and is editable in the generated config; `promptBoolOnce` for `personal` (default false) and `embedded` (default false). Every prompt has a default so `--promptDefaults` works in CI. `sourceDir` is set from `{{ .chezmoi.sourceDir }}` (the path given with `--source` at init), never a literal path.
- Shared script preamble as a chezmoi template include, `.chezmoitemplates/facts.sh`, inlined into every `after` script with `{{ template "facts.sh" . }}`. It contains: `set -eu`, Homebrew shellenv, `~/.asdf/shims` on PATH, the state directory `STATE=~/.local/state/dotfiles` (created), pure predicates `is_managed`, `app_present "<App name>.app"`, `has_command`, `default_is <domain> <key> <value>`, and marker helpers `mark <name>`, `marked <name>`, `hash_unchanged <name> <hash>` (compares a hash stored in `$STATE/<name>.hash`), `store_hash <name> <hash>`. Scripts are separate `sh` processes, so nothing exported in one script reaches the next; the include is the only mechanism. The Homebrew script does NOT include it (run-once scripts are keyed by content; a preamble edit must not re-run the installer).
- Fixed script filenames under `.chezmoiscripts/`, all templates. Only the Homebrew script is `before`. Pure writers use `run_onchange_`; every state-dependent script is `run_after_` (runs every apply) and exits early via `hash_unchanged` plus its own guards, so a skipped or failed run is retried on the next apply:
  - `run_once_before_00-homebrew.sh.tmpl` (guarded by `command -v brew` before `sudo -v`)
  - `run_after_10-packages.sh.tmpl`
  - `run_after_20-fish-plugins.sh.tmpl`
  - `run_after_21-login-shell.sh.tmpl`
  - `run_after_30-github-and-ssh.sh.tmpl`
  - `run_after_40-asdf.sh.tmpl`
  - `run_after_50-karabiner.sh.tmpl`
  - `run_onchange_after_60-defaults.sh.tmpl`
  - `run_onchange_after_61-dock.sh.tmpl`
  - `run_onchange_after_62-downloads-view.sh.tmpl`
  - `run_after_63-iterm2.sh.tmpl`
  - `run_after_64-display.sh.tmpl`
  - `run_after_90-report.sh.tmpl`
  Later issues fill these in; they must not invent other names. Marker names used across scripts: `ssh-key-generated`, `pointer-speed-applied`, `auto-brightness-applied`, `packages-status` (contains the last `brew bundle` exit code).
- Repo-only content in dot-prefixed directories where possible (`.karabiner/`, `.iterm2/`, `.downloads-view/`, `.github/`), which chezmoi ignores without rules; `docs/`, `tests/`, `README.md` and `lefthook.yml` listed in `.chezmoiignore`. Data files under `.chezmoidata/` (the cask table lives there, defined in the Brewfile issue).
- Test harness: bats for the facts template (render it with `chezmoi execute-template`, then test the functions with stubbed `profiles`, `ls`, `command`); a bats test asserting the script filenames and attributes above; shellcheck over rendered scripts; a secrets check (no `hosts.yml`, no `id_*` private keys, no token-shaped strings in the source dir); lefthook running all of it before commit.
- GitHub Actions job on a macOS runner: install chezmoi, `chezmoi init --source "$GITHUB_WORKSPACE" --promptDefaults`, `chezmoi apply --dry-run --verbose`. Dry-run validates templates and file targets only; it does not execute scripts. Script content is checked by rendering with `execute-template` in the tests, not by dry-run.
- The old README content and the 2023 `macos` script stay in place for now; later issues replace them.

## Acceptance criteria

- [ ] `chezmoi init --source <checkout> --promptDefaults` on a clean HOME renders a config with `managed`, `personal`, `embedded` and a `sourceDir` equal to the path passed
- [ ] `managed` defaults to the enrollment detection and a stored answer survives a second `chezmoi init`
- [ ] bats tests cover every predicate and marker helper in the facts template, both outcomes each, and assert the fixed script filename list
- [ ] the secrets check passes and fails when a fake `hosts.yml` is added
- [ ] shellcheck passes on every rendered script; lefthook runs bats, shellcheck and the secrets check before commit
- [ ] the GitHub Actions macOS job passes a dry-run apply on a fresh runner
- [ ] `chezmoi managed` lists no repo-only files
