# Homebrew installer and Brewfile

## PRD

[2026-09-10-chezmoi-mac-bootstrap](../prd.md)

Captured values, commands and sources are in [research-notes.md](../research-notes.md).

## What to build

Install Homebrew on a fresh Mac and declare every package from the reviewed classification.

- `run_once_before_00-homebrew.sh.tmpl`, macOS only, no shared preamble: exit if `command -v brew` succeeds; else `sudo -v`, then the official Homebrew installer, which installs the Command Line Tools headlessly when missing. No separate Command Line Tools wait loop.
- Data table `.chezmoidata/apps.yaml`: one row per cask and per App Store app with `kind` (`cask` or `mas`), `name` (Homebrew cask name or App Store id), `app` (bundle name in /Applications, e.g. `Visual Studio Code.app`), `group` (`core`, `personal`, `embedded`). Contents come from the classification in the research notes, section 9, which the user has reviewed; nothing to sort.
- Brewfile template: taps, formulae and fonts from the classification, core always, `personal` and `embedded` blocks guarded by the flags. It contains no cask or mas lines: those come from the table at run time.
- `run_after_10-packages.sh.tmpl`: render the Brewfile to a temp file; when not managed, append `cask` lines for table rows in the enabled groups whose app bundle is absent from /Applications OR whose `/opt/homebrew/Caskroom/<name>` exists (Homebrew-installed casks stay listed so `brew bundle cleanup` stays meaningful; `brew bundle` adopts existing casks by itself, so this filter is what prevents adoption), and `mas` lines for the enabled groups. Hash the temp file; if `hash_unchanged packages` and the last status was 0, exit. Else run `brew bundle --file`, write its exit code to the `packages-status` marker, store the hash, and never propagate a non-zero status (`brew bundle` continues past failing entries; a signed-out App Store or a flaky download must not abort the apply). No App Store pre-check; `mas account` no longer exists.
- On a managed Mac the script installs formulae and fonts only; the report computes the missing-apps list live from the table.
- Tests: render tests via `chezmoi execute-template --override-data` for managed/unmanaged times personal on/off (embedded on and off) assert the formulae and font blocks; bats tests for the cask filter with a stubbed Applications directory and Caskroom, asserting adopt-prevention.

## Acceptance criteria

- [ ] the table matches the classification in research notes section 9 exactly, including App Store rows
- [ ] rendered Brewfile for a managed machine contains formulae and fonts only; the script appends no cask or mas lines
- [ ] on an unmanaged machine, casks whose app exists without a Caskroom entry are not appended; casks with a Caskroom entry are
- [ ] `personal` and `embedded` entries appear only when their flag is true
- [ ] a non-zero `brew bundle` exit code lands in the marker and the apply continues
- [ ] re-running with an unchanged Brewfile and status 0 does not run `brew bundle`
- [ ] a dry-run apply on the CI runner renders the Brewfile without template errors
