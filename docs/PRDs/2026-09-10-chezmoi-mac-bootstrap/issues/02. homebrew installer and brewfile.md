## What to build

Install Homebrew on a fresh Mac and declare every package in one templated Brewfile.

- Run-once "before" script (`run_once_before_00-homebrew.sh.tmpl`), macOS only: `sudo -v`, then the official Homebrew installer, which installs the Command Line Tools headlessly when missing. No separate Command Line Tools wait loop. Every later script sets up brew's shellenv itself through the shared facts include; nothing exported here reaches other scripts.
- Cask data table `.chezmoidata/casks.yaml`: one row per cask with `cask` (Homebrew name), `app` (bundle name in /Applications, e.g. `Visual Studio Code.app`), `group` (`core`, `personal`, `embedded`). The Brewfile template iterates it; the managed-Mac report reads the same rows.
- Brewfile template: a core section for every machine, then blocks guarded by the `personal` and `embedded` flags. A cask is emitted only when not managed, and only when its app bundle is absent from /Applications OR `/opt/homebrew/Caskroom/<cask>` exists (a Homebrew-installed cask stays listed, so `brew bundle cleanup` remains meaningful). `brew bundle` adopts existing casks on its own, so this guard is what keeps "never adopt" true; a render test covers it. App Store (`mas`) entries only when not managed. Font casks always (`font-ibm-plex-mono`, `font-ibm-plex-sans`, `font-blex-mono-nerd-font`; decide whether the self-patched Blex files in the user font folder are replaced). Formulae always. Includes `chezmoi`, `asdf`, `dockutil`, `mas`. Taps `gbevin/tools` and `jesseduffield/lazygit`.
- The initial list comes from a `brew bundle dump` of the personal Mac (the leaves, casks and App Store lists in the research notes), sorted into core and groups as a proposal for the user to review. Drop the duplicate casks (`docker` vs `docker-desktop`, `google-chrome-canary` vs `google-chrome@canary`, `handbrake` vs `handbrake-app`).
- Change-triggered script (`run_onchange_after_10-packages.sh.tmpl`) that renders the Brewfile and runs `brew bundle --file` on it. Its hash comment includes the rendered Brewfile so it re-runs only when the list changes. Cleanup is never run. When `mas account` fails (App Store signed out) it sets `HOMEBREW_BUNDLE_MAS_SKIP=1` and marks `appstore-signin-needed` for the report. The bundle's exit status is recorded, not propagated, so a failing package never aborts the apply and the report still prints.
- On a managed Mac the script prints the casks from the table whose apps are missing, for Self Service requests, and marks them for the report. The bootstrap one-liner uses `--purge-binary`, so no script hunts for the installer's chezmoi binary.
- Render tests: `chezmoi execute-template` renders the Brewfile for managed/unmanaged times personal on/off (embedded on and off), with stubbed app presence and Caskroom presence, and the tests assert which casks, mas entries and blocks appear, including the no-adopt guard.

## Acceptance criteria

- [ ] the sorted core-plus-groups proposal has been reviewed and accepted by the user
- [ ] rendered Brewfile for a managed machine contains no `cask` except fonts and no `mas` entries
- [ ] rendered Brewfile for an unmanaged machine omits casks whose app already exists in /Applications
- [ ] `personal` and `embedded` blocks appear only when their flag is true
- [ ] the bundle script re-runs only when the rendered Brewfile changes and leaves manually installed packages alone
- [ ] on a managed machine the missing apps from the app list are printed
- [ ] a dry-run apply on the CI runner renders the Brewfile without template errors
