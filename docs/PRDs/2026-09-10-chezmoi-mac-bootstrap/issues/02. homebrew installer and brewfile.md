# Homebrew installer and Brewfile

Captured values, commands and sources are in [research-notes.md](../research-notes.md).

## What to build

Install Homebrew on a fresh Mac and declare every package in one templated Brewfile.

- Run-once "before" script, macOS only: `sudo -v`, then the official Homebrew installer, which installs the Command Line Tools headlessly when missing. Afterwards `eval "$(/opt/homebrew/bin/brew shellenv)"` so later scripts find brew. No separate Command Line Tools wait loop.
- Brewfile template: a core section for every machine, then blocks guarded by the `personal` and `embedded` flags. Casks are emitted only when not managed and only when the app bundle is absent from /Applications, so Homebrew never adopts an existing app. App Store (`mas`) entries only when not managed. Font casks always (`font-ibm-plex-mono`, `font-ibm-plex-sans`, `font-blex-mono-nerd-font`; decide whether the self-patched Blex files in the user font folder are replaced). Formulae always. Includes `chezmoi`, `asdf`, `dockutil`, `mas`. Taps `gbevin/tools` and `jesseduffield/lazygit`.
- The initial list comes from a `brew bundle dump` of the personal Mac (the leaves, casks and App Store lists in the research notes), sorted into core and groups as a proposal for the user to review. Drop the duplicate casks (`docker` vs `docker-desktop`, `google-chrome-canary` vs `google-chrome@canary`, `handbrake` vs `handbrake-app`).
- Change-triggered script that renders the Brewfile and runs `brew bundle --file` on it. Its hash comment includes the rendered Brewfile so it re-runs only when the list changes. Cleanup is never run.
- On a managed Mac the script prints the casks in the allow-list whose apps are missing, for Self Service requests. The installer-provided chezmoi binary is removed once Homebrew's is present.
- Render tests: chezmoi renders the Brewfile for the four combinations of managed and personal (with embedded on and off) and the tests assert which casks, mas entries and blocks appear.

## Acceptance criteria

- [ ] the sorted core-plus-groups proposal has been reviewed and accepted by the user
- [ ] rendered Brewfile for a managed machine contains no `cask` except fonts and no `mas` entries
- [ ] rendered Brewfile for an unmanaged machine omits casks whose app already exists in /Applications
- [ ] `personal` and `embedded` blocks appear only when their flag is true
- [ ] the bundle script re-runs only when the rendered Brewfile changes and leaves manually installed packages alone
- [ ] on a managed machine the missing allow-listed apps are printed
- [ ] a dry-run apply on the CI runner renders the Brewfile without template errors
