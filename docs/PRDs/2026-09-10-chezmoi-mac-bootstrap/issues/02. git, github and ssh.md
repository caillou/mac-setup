## What to build

Identity, GitHub login and per-machine ssh keys.

- `~/.gitconfig` as a plain file: personal identity default, `pull.ff = only`, `init.defaultBranch = main`, `core.commentChar = |`, and `includeIf "gitdir:~/repos/icfm/"` pointing at the managed file `~/.config/git/icfm.gitconfig` (name Pierre Spring, email `pierre.spring@icfm.ch`). The BKW and Apprentice includes are dropped. `~/.config/git/ignore` managed.
- gh: manage `~/.config/gh/config.yml` (alias `co = pr checkout`) only; never `hosts.yml`, it holds the token.
- `run_after_30-github-and-ssh.sh.tmpl`, every apply, each step guarded: when the ssh folder has no private key, generate one RSA 4096 key (`id_rsa`, hostname comment; Azure DevOps accepts RSA only) and `mark ssh-key-generated`. When `gh auth status` fails, run `gh auth login --web --hostname github.com --git-protocol ssh --skip-ssh-key --scopes admin:public_key` (the default token lacks the key-upload scope). Then `gh ssh-key add ~/.ssh/id_rsa.pub --title "$(hostname)"`, which is idempotent. Then, if the dotfiles checkout's origin is an HTTPS URL (the built-in git cloned it), switch it to `git@github.com:caillou/dotfiles.git`; optionally `ssh-keyscan github.com` into known_hosts. Once everything is in place the script prints nothing and exits.
- `~/.ssh/config` managed with agent forwarding, keep-alive and the identity file, home-relative. Never copy keys between machines.

## Acceptance criteria

- [ ] commits in a repo under `~/repos/icfm/` use the ICFM address; elsewhere the personal address, and the include works before `~/repos/icfm` exists
- [ ] on a machine without keys one RSA 4096 key is generated, uploaded to GitHub, and printed by the report for Azure DevOps; on re-run nothing changes
- [ ] gh login runs only when not authenticated; a second apply is silent
- [ ] after the script, `git -C "$(chezmoi source-path)" remote get-url origin` is the ssh URL and `git push` works (GitHub redirects the old repo name, so this does not wait for the rename)
- [ ] no key material or token exists in the repo
