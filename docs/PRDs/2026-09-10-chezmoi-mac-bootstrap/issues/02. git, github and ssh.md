## What to build

Identity, GitHub login and per-machine ssh keys.

- `~/.gitconfig` as a plain file: personal identity default, `pull.ff = only`, `init.defaultBranch = main`, `core.commentChar = |`, and `includeIf "gitdir:~/repos/icfm/"` pointing at the managed file `~/.config/git/icfm.gitconfig` (name Pierre Spring, email `pierre.spring@icfm.ch`). The BKW and Apprentice includes are dropped. `~/.config/git/ignore` managed.
- gh: manage `~/.config/gh/config.yml` (alias `co = pr checkout`) only; never `hosts.yml`, it holds the token. Run-once script (`run_once_after_30-github-and-ssh.sh.tmpl`): when `gh auth status` fails, run `gh auth login --git-protocol ssh --skip-ssh-key --scopes admin:public_key` (the default token lacks the key-upload scope); then `gh ssh-key add` the public key with the hostname as title, skipping if already registered. Then switch the dotfiles checkout's origin to `git@github.com:caillou/dotfiles.git`, because the built-in git cloned over HTTPS and pushes would have no credentials.
- ssh: when the ssh folder has no private key, generate one RSA 4096 key (`id_rsa`) with a hostname comment, because Azure DevOps accepts RSA only. Print the public key with the instruction to paste it into Azure DevOps. `~/.ssh/config` managed with agent forwarding, keep-alive and the identity file, home-relative. Never copy keys between machines.
- Marks `ssh-key-generated` in the state directory when a key was created, so the report prints the Azure DevOps paste instruction with the key.

- [ ] the ICFM include works before `~/repos/icfm` exists

- [ ] after the script, `git -C "$(chezmoi source-path)" remote get-url origin` is the ssh URL and `git push` works
