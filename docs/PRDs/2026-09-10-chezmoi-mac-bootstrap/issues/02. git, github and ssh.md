## What to build

Identity, GitHub login and per-machine ssh keys.

- `~/.gitconfig` as a plain file: personal identity default, `pull.ff = only`, `init.defaultBranch = main`, `core.commentChar = |`, and `includeIf "gitdir:~/repos/icfm/"` pointing at an ICFM identity file (`pierre.spring@icfm.ch`) that lives in the repo, for example under `~/.config/git/`. The BKW and Apprentice includes are dropped. `~/.config/git/ignore` managed.
- gh config with the `co = pr checkout` alias. Run-once script: when `gh auth status` fails, run the browser login with ssh protocol and no key upload prompt; then `gh ssh-key add` the public key with the hostname as title, skipping if already registered.
- ssh: when the ssh folder has no private key, generate one RSA 4096 key (`id_rsa`) with a hostname comment, because Azure DevOps accepts RSA only. Print the public key with the instruction to paste it into Azure DevOps. `~/.ssh/config` managed with agent forwarding, keep-alive and the identity file, home-relative. Never copy keys between machines.
- Ordering: this module runs before the keyboard projects so they can clone over ssh.

## Acceptance criteria

- [ ] commits in a repo under `~/repos/icfm/` use the ICFM address; elsewhere the personal address
- [ ] the ICFM include works before `~/repos/icfm` exists
- [ ] on a machine without keys one RSA 4096 key is generated, uploaded to GitHub, and printed for Azure DevOps; on re-run nothing changes
- [ ] gh login runs only when not authenticated
- [ ] no key material or token exists in the repo
